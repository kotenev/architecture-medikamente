## 2. Механизм тегирования данных

### 2.1 Схема тегов

```yaml
# Структура тега данных
DataTag:
  id: string                    # Уникальный идентификатор
  data_classification:          # Классификация
    level: 1-4                  # Уровень конфиденциальности
    category: string            # PII | PHI | Financial | Internal
    subcategory: string         # Детализация категории
  protection_requirements:      # Требования защиты
    encryption_at_rest: boolean
    encryption_in_transit: boolean
    hsm_required: boolean
    anonymization_required: boolean
  access_control:               # Контроль доступа
    allowed_roles: list         # Разрешённые роли
    purpose_limitation: list    # Допустимые цели использования
  retention:                    # Хранение
    retention_period: duration  # Срок хранения
    deletion_policy: string     # Политика удаления
  audit:                        # Аудит
    audit_level: string         # full | standard | minimal
    log_access: boolean
    log_modifications: boolean
```

## 3. Список инструментов и мер защиты

### 3.1 Шифрование

| Компонент                 | Инструмент                        | Описание                            |
|---------------------------|-----------------------------------|-------------------------------------|
| Шифрование файлов at-rest | BitLocker / LUKS                  | Шифрование дисков файлового сервера |
| Шифрование БД             | TDE (Transparent Data Encryption) | Для PostgreSQL/1C при миграции      |
| Управление ключами        | HashiCorp Vault / HSM             | Централизованное управление ключами |
| Шифрование in-transit     | TLS 1.3                           | Все сетевые взаимодействия          |
| Шифрование email          | S/MIME / PGP                      | Защита интеграции с лабораторией    |

### 3.2 Контроль доступа

| Компонент           | Инструмент                     | Описание                              |
|---------------------|--------------------------------|---------------------------------------|
| Identity Management | Active Directory + RBAC        | Расширение текущего AD                |
| MFA                 | Microsoft Authenticator / TOTP | Двухфакторная аутентификация          |
| PAM                 | CyberArk / Teleport            | Управление привилегированным доступом |
| API Gateway         | Kong / Nginx + OAuth2          | Для будущих интеграций                |

### 3.3 Мониторинг и аудит

| Компонент  | Инструмент                     | Описание                           |
|------------|--------------------------------|------------------------------------|
| SIEM       | Wazuh / ELK Stack              | Сбор и анализ событий безопасности |
| File Audit | Windows File Auditing + Sysmon | Аудит доступа к файлам             |
| DLP        | Microsoft Defender DLP         | Предотвращение утечек              |
| UEBA       | Microsoft Sentinel             | Поведенческий анализ               |

### 3.4 Анонимизация и обфускация

| Компонент              | Инструмент            | Описание                  |
|------------------------|-----------------------|---------------------------|
| Маскирование данных    | Delphix / Informatica | Динамическое маскирование |
| Анонимизация медданных | DICOM Anonymizer      | Для медицинских снимков   |
| Псевдонимизация        | Custom tokenization   | Замена ПДн токенами       |

## 4. Матрица применения мер по потокам данных

| Поток данных                  | Меры at-rest                 | Меры in-transit   | Контроль доступа | Аудит    |
|-------------------------------|------------------------------|-------------------|------------------|----------|
| Пациент → Регистрация         | -                            | -                 | Физический       | Журнал   |
| Регистрация → Файловый сервер | BitLocker, TDE               | TLS 1.3 (SMB 3.0) | RBAC             | Full     |
| Врач → Журнал записей         | BitLocker                    | TLS 1.3           | RBAC по врачу    | Full     |
| Врач → Данные пациента        | BitLocker + field encryption | TLS 1.3           | RBAC + consent   | Full     |
| Лаборатория → Реестр          | BitLocker                    | S/MIME            | API Key + RBAC   | Full     |
| Кассир → ККМ → 1С             | TDE                          | TLS 1.3           | RBAC             | Standard |
| 1С → Склад                    | TDE                          | OLE → API + TLS   | RBAC             | Standard |

## 5. Roadmap внедрения

### Фаза 1 (1-2 месяца): Критические меры
- Внедрение BitLocker на файловом сервере
- Настройка SMB 3.0 с шифрованием
- Реструктуризация папок (удаление ПДн из имён)
- Базовая настройка RBAC в AD
- Включение File Auditing в Windows

### Фаза 2 (3-4 месяца): Усиление защиты
- Внедрение HashiCorp Vault
- Настройка DLP
- Развёртывание SIEM (Wazuh)
- Защита интеграции с лабораторией (S/MIME)

### Фаза 3 (5-6 месяцев): Governance
- Внедрение Apache Atlas / OpenMetadata
- Автоматическое тегирование данных
- Политики хранения и удаления
- Обучение персонала
